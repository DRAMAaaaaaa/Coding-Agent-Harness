# 公网 IP Mock 演示部署设计

## 1. 背景与目标

项目已在阿里云中国香港 ECS 上通过 Docker Compose 运行，Harness 监听宿主机 `127.0.0.1:8000`。本机探测已证明 Uvicorn 正常响应，但公网 `80/443/8000` 尚不可访问。用户明确选择不购买域名，并批准只通过 `http://47.76.86.198` 演示确定性的 Mock Harness，不使用 DeepSeek/Qwen 或任何真实 API Key。

本次目标是在不公开容器端口、不削弱容器隔离的前提下，为单次课程演示增加公网 HTTP 入口。公网请求由 Nginx 接收并反向代理至 `127.0.0.1:8000`，应用仅信任指定公网 IP 的 Host 与 Origin。

## 2. 范围

### 2.1 本次交付

- 新增仅供 ECS 使用的 Compose 覆盖配置，不改变本地默认 Compose 的 localhost 安全行为。
- 允许部署入口显式配置可信公网 Host 与 Origin；缺失配置时继续 fail closed。
- 提供 Nginx 配置，将公网 `80` 转发到宿主 `127.0.0.1:8000`。
- 保留 `ScriptedMockProvider`、只读内置示例项目、只读容器文件系统、能力删除和独立状态卷。
- 提供阿里云安全组、ECS 安装、启动、验证、停止和撤销步骤。
- 用自动化测试证明默认本地模式未扩大暴露面，公网覆盖只接受明确配置的 IP。

### 2.2 明确不做

- 不配置域名、TLS/HTTPS、自动证书或 CDN。
- 不在公网输入、保存或调用 DeepSeek/Qwen API Key。
- 不允许选择任意宿主项目路径，不挂载用户主目录或凭据目录。
- 不增加公网用户认证、多租户、持久凭据或任意 Shell 能力。
- 不开放宿主 `8000`、Docker API、数据库或管理面板端口。
- 不把该配置描述为生产部署；它只用于短时课程 Mock 演示。

## 3. 架构与数据流

```text
浏览器 http://47.76.86.198
  -> 阿里云安全组 TCP/80
  -> ECS Nginx :80
  -> 127.0.0.1:8000
  -> Harness 容器 :8000
  -> ScriptedMockProvider + 只读示例仓库
```

Nginx 保留客户端的公网 Host，并显式传递 `Host`、`X-Forwarded-For`、`X-Forwarded-Proto`。Harness 的会话护栏将可信 Host 配置为 `47.76.86.198`，可信 Origin 配置为 `http://47.76.86.198`；浏览器提交修改类请求时仍需同时提供同源 Origin 与进程内临时会话 Token。

部署配置不得把容器端口改为 `0.0.0.0:8000`。公网只暴露 Nginx 的 80 端口，使后端继续只能由宿主反向代理访问。

## 4. 配置边界

公网覆盖通过显式环境变量接收，并只接受本次批准的固定演示地址：

- `HARNESS_PUBLIC_HOST=47.76.86.198`
- `HARNESS_PUBLIC_ORIGIN=http://47.76.86.198`

启动入口只在公网演示模式下读取这两个值，并将其加入可信 Host/Origin。两者必须成对存在并精确等于 `47.76.86.198` 与 `http://47.76.86.198`；其他地址、非法值或缺失值均使服务拒绝启动。Nginx 的固定 `server_name` 与同一地址保持一致。默认本地入口继续只信任实际监听端口上的 `127.0.0.1` 和 `localhost`。

公网覆盖继续固定 `HARNESS_LLM_PROVIDER=mock`，不接受 `.env` 中的模型 Key。运行项目仍是仓库内 `examples/python_demo` 的只读挂载，状态只写入专用 Docker 卷。

## 5. Nginx 与网络策略

Nginx 仅创建一个端口 80 的站点：

- `server_name 47.76.86.198`；其他 Host 直接拒绝。
- 请求体设置小型上限，并设置适合任务事件流的读取超时。
- 对 SSE 关闭代理缓冲，避免时间线事件延迟。
- 增加基础安全响应头，但不声明 HSTS，因为本方案没有 HTTPS。
- 不记录请求正文或会话 Token；使用默认访问日志时不得包含自定义会话头。

阿里云安全组只向公网开放 TCP 80；TCP 22 仍限制为管理员 IP；443、8000 和其他端口保持关闭。演示结束后，停止 Nginx 或删除安全组 80 规则，并停止演示容器。

## 6. 错误处理与验证

部署前后逐层验证：

1. 容器健康：`docker compose ps`。
2. 后端本机 GET：`curl http://127.0.0.1:8000/` 返回 WebUI。
3. Nginx 配置：`nginx -t` 通过。
4. ECS 本机代理：带指定 Host 请求 `http://127.0.0.1/` 返回 WebUI。
5. 外部网络：`http://47.76.86.198` 可加载 WebUI。
6. 浏览器纵向路径：接入固定示例、生成计划、批准、运行、查看反馈和最终 diff。
7. 负向验证：公网 `:8000` 不可达；错误 Host 被拒绝；页面不提供真实 Provider 凭据入口或不使用该入口。

若本机 8000 正常而公网 80 超时，优先检查阿里云安全组和 Nginx监听；若页面能加载但修改请求返回 `403 SESSION_REQUIRED`，检查 Nginx 的 Host 保留及 Harness 的可信 Host/Origin 是否与浏览器地址完全一致。

## 7. TDD 与交付

实施采用红—绿—重构：先增加失败的配置与交付契约测试，覆盖公网 Host/Origin 成对校验、固定地址拒绝、默认 localhost 行为、公网覆盖仍绑定宿主 localhost、Mock 固定、基础启动入口消费环境变量和 Nginx/SSE 契约；再进行最小实现。Compose 渲染命令必须显式提供两个非秘密变量。最终运行聚焦测试、完整一键测试、三机制演示、秘密扫描、Compose 配置渲染、容器化 Nginx 语法检查（Docker daemon 可用时）及 `git diff --check`。

设计和实现分别提交中文 Git 记录。真实 ECS 操作由用户在自己的终端执行；仓库不保存 ECS 登录信息、密码、SSH 私钥或 API Key。

## 8. 使用期限与风险声明

HTTP 会以明文传输页面和请求，当前又没有用户认证，因此此方案只适合用户在场的短时 Mock 答辩。它不能承载真实密钥、隐私项目或长期公网服务。演示结束后必须撤销 80 端口；如果以后需要长期展示，应改为域名、HTTPS、身份认证、速率限制和经过公网安全评审的部署方案。
